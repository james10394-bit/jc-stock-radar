# 台股法人技術分析站 v2.6.0

本版新增開盤量能觀察、最多3檔風控候選、持倉固定停損與資料完整性檢查。這是規則型研究工具，尚未以完整歷史資料回測獲利、勝率、交易成本與滑價；多空分數不是上漲機率。

## 先更新網站

1. 解壓縮整包，在原本 `jc-stock-radar` 儲存庫根目錄上傳並覆蓋檔案；必須包含新增的 `risk-engine.js`、`intraday-ui.js`、`scripts/intraday.py`、`scripts/trading_calendar.py`。不要直接上傳 ZIP。
2. 確認 `.github/workflows/update.yml` 與新增的 `.github/workflows/intraday.yml` 也已上傳。若拖曳時 `.github` 沒進去，進入 GitHub 的 `.github/workflows` 資料夾，上傳這兩個 YAML 檔；不可只放在儲存庫根目錄。
3. 到 Actions 執行 **Update TWSE data → Run workflow**，等待成功。第一次需要補歷史缺漏，較久是正常的。先確認 `data/market.json` 已有 `trading_sessions`、`calendar_verified_at` 與 2.6.0 版本，再使用選股功能。
4. 到 Actions 執行 **Opening market snapshots → Run workflow** 測試快照。設定中 Actions 的 Workflow permissions 需允許 Read and write permissions，否則機器人不能儲存更新。
5. 等 GitHub Pages 部署完成，重新整理網站並確認標頭 v2.6.0。本包不包含舊的 `market.json`，避免覆蓋目前資料。原本的自選設定仍由瀏覽器保存；原有 `data/watchlist.json` 與 `data/risk_config.json` 不必重新上傳。

## 要持續取得盤中成交快照

1. 電腦安裝 Python 3.11 以上版本，整包解壓縮。
2. **交易日09:00之前**雙擊 `Start-Live.bat`，保持視窗與電腦開啟。它會自動下載網站盤後資料，開啟 `http://127.0.0.1:8765`。請使用這個本機頁面。
3. 本機程式每輪抓完所有普通股後等待30秒再抓下一輪；整輪可能耗時更久，網路失敗或交易所服務限制也會延遲，不能視為逐筆即時行情。畫面顯示實際成交時間，超過2分鐘的報價不產生候選。
4. 本機服務只監聽電腦本身，手機無法直接連入這個 localhost 網址。手機上的 GitHub Pages 使用排程快照，不能保證09:00準時或30秒更新。若要手機持續即時，需另行部署常駐後端與適當行情服務；本版沒有宣稱已完成這項部署。

GitHub Actions 另設交易日09:00～13:30每5分鐘排程；排程與 Pages 發布都可能延遲，**不是即時服務**。若未取得09:05附近的實際觀測，不會以後來的成交量假裝開盤量。

## 開盤篩選規則

- 09:00開始收資料；09:04:45～09:05:30之間實際成交快照，作為開盤約5分鐘累計量。保留每檔實際觀測時間，不是假設精準09:05:00。
- 限上市／上櫃普通股；每產業最多1檔，最多3檔，未達條件可為0檔。ETF 等其他證券仍能查詢，但不套用普通股 EPS 買進篩選。
- 開盤觀測量至少500張、開盤價乘觀測量至少2,000萬元，且占前20日平均**整日**成交量至少8%。這個指標不是「同時段量比」。類股成交金額以成交價乘累計量估算，不是交易所逐筆成交金額。
- 需有官方交易日曆、連續30個交易日有效OHLCV、近5日法人，最新累計EPS為正且財報期別可用。
- 排除跌回開盤價以下、較開盤價追高超過3%、均線轉弱、過大乖離、KD過熱，以及外資當日與近5日同步賣超。
- 結構停損距離需在0.5%～8%，至前20日高點的潛在報酬／風險至少2倍。停損距離與倍數是本版設定值，未經回測驗證。
- 當日法人還沒公布前，使用前一完整交易日法人；不宣稱知道盤中外資當日淨買賣超。沒有使用當日收盤後才出現的法人資料選開盤候選。
- 資料缺漏、報價超過2分鐘、行情批次失敗、沒觀測到開盤時段或休市時不補排名、不產生目前買進候選。

## 國喬案例對應的修正

- 虧損或缺少EPS不再被技術偏多訊號蓋過。
- 停損距離太遠／報酬風險不足，明確停止新買進候選。
- 不再把任意權重的買賣比例寫成勝率；低KD或跌到支撐不單獨加分。
- 修補歷史交易日缺漏，缺漏未補齊前不顯示可用的技術建議。
- 「3日大戶持股比例」原先實際是法人淨買超除成交量，已更正名稱，不冒充股權分散表。
- 輸入真實成本、股數與固定停損後計算損益；儲存的停損不可往下移，觸及會警示。這不是自動停損單，跳空／流動性不足時也不能保證停損成交。

價量歷史仍是原始日行情，尚未完成除權息、分割的完整還原與事件調整；這可能影響均線及漲跌判讀。累計EPS不等於TTM EPS；舊估值面板的「由價格／本益比反推EPS」只是推估，不能取代正式四季財報。產業分類也不等於完整的產業研究。請先以紙上交易驗證，不能據此保證避免虧損。

## 驗證

執行 `python -m unittest discover -s tests -q` 與 `node tests/test_risk_engine.js`。本版通過25項Python測試、20項風控回歸測試及6個本機HTTP路由檢查。另實際驗證MIS可以取得當日成交快照，以及官方月報可補回10月初被漏掉的交易日。尚未進行真實開盤連續整場觀測、手機實機驗證及策略績效回測。
